# AGENTS.md

Zig 0.16.0 port of the `automerge` CRDT library. Read this before editing.

## Layout

- `src/root.zig` is the root module and re-exports the public modules. Public
  module names are `zautomerge.<name>` and mirror the Rust module names, so the
  two trees are diffable. The file layout mirrors the Rust layout: flat under
  `src/`, with `src/opset/` and `src/hexane/` as the only subdirectories.
- `docs/plan.md` is the port plan: phase order, module map, Zig mapping rules,
  verification gates, risks. Read the phase you are working in.
- `docs/survey/` is the API survey of the Rust reference, one file per slice,
  with `path:line` citations into the upstream source. Read the section that
  covers your change; do not work from memory of the Rust code.
- `API.md` is the target public surface. It is a contract, not a description of
  what exists.
- `PROJECT.md` is the status: what is implemented, what is planned, and the
  compatibility contract.
- `test/` holds tests and the fixture corpus. It arrives with P0; until then
  it does not exist. `test/golden/` is generated by the oracle, not
  hand-edited.
- `tools/oracle/` is a cargo crate that drives the Rust reference
  implementation. It is a development tool, not part of the port. It reaches
  the reference through a symlink to `$AUTOMERGE_REF/rust/automerge`.

## Reference checkout

`../github-automerge-automerge` is a read-only upstream checkout, exported as
`AUTOMERGE_REF`. Never build in it, never modify it, never commit into it. When
you need upstream behaviour, read the survey or the Rust source; when you need
upstream behaviour *executed*, extend the oracle crate.

## Invariants

- Never change the document format, the change encoding, the column ids, the
  column order, or the sync message bytes. These are the compatibility
  contract. A change hash is SHA-256 over the encoded change, so any change to
  the encoder changes every hash and every existing document.
- `save()` output is not required to be byte-identical to the reference;
  DEFLATE is not reproducible across implementations. Equivalence is checked by
  loading and comparing the materialized document.
- Every entry point that allocates takes a `std.mem.Allocator`. Do not use the
  page allocator, and do not hide the allocator in a global.
- Every parser is total over untrusted input: a `ParseError`, never a panic,
  never an unbounded loop, never an unchecked allocation size. The 8 fixtures
  in the upstream `tests/fuzz-crashers/` are the regression suite for this.
- Slices returned into a document's own storage are valid until the next
  mutation. If a caller could hold one across a mutation, return a copy.
- Do not port upstream dead code. The verified list is in
  [docs/plan.md](docs/plan.md) §2: `op_set2/skip_list.rs`, `query/`,
  `indexed_cache.rs`, and the `hexane` `deep_fuzz` and `bijou64` features.

## Method

- One phase at a time. A phase is done when its gate command passes, not when
  the code compiles.
- Port upstream tests case-for-case. A test that asserts a Rust type's layout
  is dropped; a test that asserts behaviour is kept. A test that cannot be
  ported has its gap written down in the same commit.
- Every non-obvious claim about upstream behaviour needs a `path:line`
  citation, in the code comment or in the commit description.
- Do not add a dependency without a reason recorded in the commit. The port
  currently needs none.

## Commands

- `zig build` makes the module available to consumers.
- `zig build test` runs the unit tests.
- `zig build conformance` regenerates `test/golden/` from the oracle.
- `zig fmt --check .` checks formatting. `gate` runs the house gate.
- `jj st` shows working-copy status. Use `jj`, not raw Git, for mutations.

This NixOS project declares development dependencies and tools in
`devenv.nix`. Do not install system or development libraries imperatively. Use
direnv or `devenv shell`; run `direnv allow` after changing the environment.
